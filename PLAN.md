## Концепция

**Focus Champ** — веб-приложение (PWA) для ежедневных соревнований по привычкам и целям между пользователями.

### Суть
Пользователь создаёт «комнату соревнования», добавляет в неё ежедневные задачи с очками, приглашает друзей по коду комнаты. Каждый день участники отмечают выполнение задач. По окончании дня очки суммируются — объявляется победитель дня. Некоторые задачи могут требовать подтверждения: пользователь отправляет скриншот (например, из трекера сна), AI анализирует его и автоматически подтверждает или отклоняет выполнение.

### Ключевые отличия от конкурентов (из market research)
1. **AI-верификация скриншотов** — ни у кого нет
2. **Пользовательские комнаты с кодом** — кастомные задачи, любые домены (сон, спорт, экранное время)
3. **Мульти-доменность** — не только фитнес (как Strava) или фокус (как Forest), а любые привычки
4. **Peer-review арбитраж** — оспаривание AI-решения через голосование участников

## MVP

Минимальный жизнеспособный продукт включает **фазу 1 (Core)**. Это всё, что нужно для тестирования гипотезы на первых пользователях.

### MVP включает:

| Модуль | Что входит |
|--------|-----------|
| **Аутентификация** | Регистрация по логину/паролю, вход, выход |
| **Комнаты** | Создание, код, присоединение, просмотр |
| **Задачи** | Добавление с очками, отметка выполнения |
| **Подсчёт** | Автоматический подсчёт очков, победитель дня |
| **AI-верификация** | Загрузка скриншота, анализ → подтверждение/отклонение |

### MVP НЕ включает (будет потом):
- ❌ Друзья, поиск, заявки
- ❌ Общий лидерборд
- ❌ Оспаривание AI / peer-review
- ❌ Длительность соревнований (MVP: только бесконечные)
- ❌ Персонаж, уровни, ачивки
- ❌ Видео-верификация
- ❌ Шаблоны комнат
- ❌ Денежные ставки
- ❌ Восстановление пароля
- ❌ PWA (push-уведомления) — только базовая установка

### Критерии готовности MVP:
1. Пользователь может зарегистрироваться и войти
2. Создать комнату с 2-3 задачами
3. Поделиться кодом, другой пользователь присоединяется
4. Отмечать задачи, видеть статус других
5. Загрузить скриншот → AI проверяет → начисляет/не начисляет очки
6. По окончании дня видеть победителя

## Экраны и пользовательские сценарии

### 1. Экран регистрации `/register`
- Поле «Логин»
- Поле «Пароль»
- Поле «Повторите пароль»
- Кнопка «Зарегистрироваться»
- Ссылка «Уже есть аккаунт? Войти»

### 2. Экран входа `/login`
- Поле «Логин»
- Поле «Пароль»
- Кнопка «Войти»
- Ссылка «Нет аккаунта? Зарегистрироваться»
- (Будущее) Ссылка «Забыли пароль?»

### 3. Основной экран `/dashboard`
После входа пользователь попадает сюда. Здесь:
- Приветствие «Привет, {ник}!»
- Карточка персонажа (заглушка в MVP: иконка)
- Список активных комнат (в которых участвует)
- Кнопка «Создать комнату» (основной CTA)
- Кнопка «Присоединиться» (ввод кода)
- Нижняя навигация (менюшка):
  - 🏠 Главная (активна)
  - 👥 Друзья (серым, неактивно → «Скоро»)
  - 🏆 Лидерборд (серым)
  - 👤 Профиль

### 4. Создание комнаты `/room/create`
- Поле «Название комнаты»
- Секция «Задачи»:
  - Кнопка «+ Добавить задачу»
  - Для каждой задачи:
    - Название задачи (текст)
    - Очки за выполнение (число)
    - Чекбокс «Требуется подтверждение» (AI-верификация)
    - Кнопка удалить ✕
- Кнопка «Создать комнату» → переход на экран комнаты с показом кода

### 5. Присоединение к комнате `/room/join`
- Поле ввода «Код комнаты» (6 символов)
- Кнопка «Присоединиться»
- Обработка ошибок: «Комната не найдена», «Вы уже участник»

### 6. Комната (основной игровой экран) `/room/[id]`
Самый важный экран. Компоновка:
- **Верх**: Название комнаты, код комнаты, длительность (MVP: «День {N}»)
- **Арена персонажей**: Все участники комнаты **обязательно** отображаются в виде своих 3D-персонажей (роблокс-стайл модельки). Персонажи расставлены по кругу лицом друг к другу, анимированы в «боевой стойке» (руки согнуты, лёгкое покачивание) — как будто они соревнуются/борются между собой. У каждого уникальный цвет, никнейм под моделькой. Победитель дня подсвечивается золотым контуром 🥇. Это создаёт живое ощущение присутствия и соревновательного духа. (Подробно: [`docs/SCREENS.md#арена-персонажей-3d`](docs/SCREENS.md))
- **Середина**: Текущий день, список задач:
  - Каждая задача — карточка:
    - Название задачи
    - Очки
    - Статус (для тебя): «Не выполнено» / «На проверке» / «✅ Подтверждено» / «❌ Отклонено»
    - Статус других участников: иконки игроков
    - Кнопка «Отметить выполнение» (если без AI)
    - Кнопка «Загрузить подтверждение» (если с AI) → модалка загрузки скриншота
- **Низ**: Турнирная таблица дня:
  - Место | Игрок | Очки | Прогресс
  - Прогресс-бар набранных очков
- **По окончании дня**: баннер «🏆 {Имя} выиграл день {N}!»

### 7. Загрузка скриншота (модальное окно)
- Drag-and-drop или кнопка выбора файла
- Превью загруженного изображения
- Кнопка «Отправить на проверку»
- После отправки — лоадер «AI анализирует...»
- Результат: ✅ Подтверждено (+N очков) или ❌ Отклонено (причина)

### 8. Профиль `/profile`
- Никнейм (редактируемый)
- Аватар (заглушка)
- Статистика: всего побед, всего комнат, всего очков
- Кнопка «Выйти»

### Поток AI-верификации
```
1. User загружает скриншот → Uploadthing
2. Client отправляет URL скриншота → POST /api/verify
3. Server скачивает изображение → отправляет в Gemini Vision API
4. Gemini возвращает структурированный ответ (JSON):
   {
     "verified": true/false,
     "extracted_data": { "sleep_hours": 7.5, "date": "2026-05-30", ... },
     "confidence": 0.95,
     "reasoning": "Видно 7.5 часов сна за 30 мая, что соответствует условию задачи."
   }
5. Server сохраняет результат, начисляет/не начисляет очки
6. SSE-событие → все клиенты в комнате получают обновление
```

### Real-time через SSE
```
GET /api/rooms/[id]/events
→ text/event-stream
→ События: "player_scored", "task_verified", "day_ended", "new_player"

Каждые 30 секунд клиент переподключается (keepalive).
При изменении данных — сервер отправляет событие всем подписчикам комнаты.
```

## Схема базы данных

> Prisma schema, ключевые модели:

### User
```prisma
model User {
  id           String   @id @default(cuid())
  username     String   @unique
  passwordHash String
  displayName  String?
  avatarUrl    String?
  createdAt    DateTime @default(now())
  updatedAt    DateTime @updatedAt

  // Relations
  memberships  RoomMember[]
  taskSubmissions TaskSubmission[]
  createdRooms Room[]
  sentFriendRequests     FriendRequest[] @relation("fromUser")
  receivedFriendRequests FriendRequest[] @relation("toUser")
  wonDays     DayWinner[]
}
```

### Room (комната соревнования)
```prisma
model Room {
  id          String   @id @default(cuid())
  name        String
  joinCode    String   @unique  // 6-символьный код
  duration    Int?              // null = бесконечно, иначе кол-во дней
  status      RoomStatus @default(ACTIVE) // ACTIVE, COMPLETED, CANCELLED
  creatorId   String
  createdAt   DateTime @default(now())
  endedAt     DateTime?

  creator     User      @relation(fields: [creatorId], references: [id])
  tasks       Task[]
  members     RoomMember[]
  days        CompetitionDay[]
}

enum RoomStatus {
  ACTIVE
  COMPLETED
  CANCELLED
}
```

### Task (задача в комнате)
```prisma
model Task {
  id              String   @id @default(cuid())
  roomId          String
  title           String
  points          Int
  requiresVerification Boolean @default(false)
  verificationType String?  // "screenshot", "video", null (если без проверки)
  sortOrder       Int     @default(0)
  createdAt       DateTime @default(now())

  room       Room         @relation(fields: [roomId], references: [id])
  submissions TaskSubmission[]
}
```

### RoomMember (участник комнаты)
```prisma
model RoomMember {
  id        String   @id @default(cuid())
  roomId    String
  userId    String
  joinedAt  DateTime @default(now())

  room      Room @relation(fields: [roomId], references: [id])
  user      User @relation(fields: [userId], references: [id])

  @@unique([roomId, userId])
}
```

### CompetitionDay (игровой день)
```prisma
model CompetitionDay {
  id        String    @id @default(cuid())
  roomId    String
  dayNumber Int
  date      DateTime  @default(now())
  status    DayStatus @default(ACTIVE)  // ACTIVE, COMPLETED
  winnerId  String?

  room      Room        @relation(fields: [roomId], references: [id])
  winner    DayWinner?
  scores    DayScore[]

  @@unique([roomId, dayNumber])
}

enum DayStatus {
  ACTIVE
  COMPLETED
}
```

### DayScore (очки игрока за день)
```prisma
model DayScore {
  id        String @id @default(cuid())
  dayId     String
  userId    String
  totalPoints Int  @default(0)

  day       CompetitionDay @relation(fields: [dayId], references: [id])
}
```

### TaskSubmission (отметка о выполнении задачи)
```prisma
model TaskSubmission {
  id          String        @id @default(cuid())
  taskId      String
  userId      String
  dayId       String
  status      SubmissionStatus @default(PENDING) // PENDING, VERIFIED, REJECTED, DISPUTED
  proofUrl    String?       // URL скриншота/видео
  aiResponse  Json?         // Ответ от AI (структурированный)
  createdAt   DateTime      @default(now())
  reviewedAt  DateTime?

  task        Task          @relation(fields: [taskId], references: [id])
  user        User          @relation(fields: [userId], references: [id])
  day         CompetitionDay @relation(fields: [dayId], references: [id])

  @@unique([taskId, userId, dayId])
}

enum SubmissionStatus {
  PENDING
  VERIFIED
  REJECTED
  DISPUTED
}
```

### DayWinner (победитель дня)
```prisma
model DayWinner {
  id        String @id @default(cuid())
  dayId     String @unique
  userId    String

  day       CompetitionDay @relation(fields: [dayId], references: [id])
  user      User           @relation(fields: [userId], references: [id])
}
```

### FriendRequest (заявки в друзья — Фаза 2)
```prisma
model FriendRequest {
  id        String   @id @default(cuid())
  fromUserId String
  toUserId   String
  status    FriendRequestStatus @default(PENDING)
  createdAt DateTime @default(now())

  fromUser  User @relation("fromUser", fields: [fromUserId], references: [id])
  toUser    User @relation("toUser", fields: [toUserId], references: [id])

  @@unique([fromUserId, toUserId])
}

enum FriendRequestStatus {
  PENDING
  ACCEPTED
  REJECTED
}
```

### Friendship (подтверждённая дружба — Фаза 2)
```prisma
model Friendship {
  id        String   @id @default(cuid())
  user1Id   String
  user2Id   String
  createdAt DateTime @default(now())

  @@unique([user1Id, user2Id])
}
```
